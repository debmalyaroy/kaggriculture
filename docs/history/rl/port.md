Layers chain through three name conventions (`agent`, `cha20_entry_agent`, `*_agent` / `_HOST =
last callable`). The Rust chain is an explicit ordered list, so the naming quirks disappear, but
**the order must be the Python call order**. The Kaggle entry point = the last callable
(`ig_agent` in cha22, then our RSA wrapper via the entry footer).

## 2. Stateful parts that must be ported exactly

- Per-player state dicts keyed by `observation['player']`, reset when `step <= state['step']`
  (new episode): `_RACE_STATE`, `_R37_PLAYERS`, `_R37_HORIZONS`, `_V9_ITEM_HZ`, `_FX_STATE`,
  `_BD_STATE`, `_MPX_HIST`, `_E343_WL_STATE`, `_PIPE_STATE`, `_MA_STATE`, `_CA_STATE`, ...
- The chassis ledgers: `sell_state['r36_debts']`, `pending` queues, route id, opening flags.
- PIPE mutates `routes[0][:96]` in place at the first call of a game (EarlyCycle mode). The
  Rust base applies the same transform at episode start (it is a pure function of the mode).
- `_CXD_MODELS` / `_CXD_PARENT_ORDERS` (order-book models captured from parent actions).
- Report/telemetry dicts are NOT behaviour; they become typed counters (useful for the guards).

## 3. Determinism traps

- Python dict iteration order = insertion order: every place that iterates a dict to build
  orders must use the same order (Vec/IndexMap in Rust).
- `sorted(..., key=...)` stability and tie-breaks; `max()` returns the first maximum.
- Float arithmetic: prices are ints from the engine; realized/trailing averages are floats.
  Keep f64 and the same operation order.
- `round()` is banker's rounding in Python.
- `int(x)` truncates toward zero.
- Exceptions caught per layer (`except Exception: return action`) change behaviour on bad
  input. Rust layers must return the parent action in exactly the cases Python would raise
  (index errors, missing keys).

## 4. Method (tasks P2.3-P2.13)

1. Recordings: ~600 Python v61.1 games (our seat's observations + actions) in
   `data/recordings/r1/v61.1/<RUNID>/`.
2. Truncated references: `python/ref` builds the Python agent with entry = layer k.
3. Open-loop parity: the Rust chain up to k on the recorded observations must reproduce the
   truncated Python actions exactly, every step. The first divergence per game is reported.
4. Closed-loop parity: identical banks vs the same opponents on the Rust engine.
5. Latency: binary max <= 500 us/turn; bridge + binary p99 <= 1 ms.

## 6. Latency pass (P2.15, 2026-09-24 21:30Z)

Every change below is bit-exact. Checked against 600 random-population selfplay games (identical
banks) and `parity.py check --cut full` 8/8.

- **CXD / V44Y** share `layers::tail::Margin`:
  - candidates are index maps, not cloned order lists;
  - per-item schedule keys are packed `Sched` arrays hashed with FNV;
  - `market::price_i` memoises the pure price curve per thread;
  - V44Y's permutation dedupe is a `HashSet` (it was an O(n²) `Vec::contains`).
- **r51 input beam**: candidates are ranked before their path/used vectors are built. The `path`
  tiebreak is (parent path, new stop), because every beam at a depth has the same path length.
- **Terminal planner**: `Sim::liquidate` is memoised on exact physical state. Its output depends
  only on unit positions, inventories and the shed.
- Result (12 games, machine under gate load): turns over 1 ms dropped from 278 to 130; CXD max
  4.3 → 1.3 ms; V44Y 5.4 → 2.2 ms; r51 3.0 → 1.2 ms; step 712 ~12 → ~6 ms.
- **Engine interning (21:30Z):** `Cell` names and `OMap` keys are `&'static str` via
  `state::name` (known names are static; unknown names are leaked once). Exact: engine tests
  29/29, 600/600 banks, parity 8/8. Planner simulation time 45 → 37 ms per 10 plans.
- **Remaining:**
  - The planner does ~60 simulations at ~60 µs each (step 712 ≈ 4–6 ms). Spread over the
    per-command `UnitAction` String allocs, row snapshots and validation. A sub-ms step 712
    needs fewer simulations (algorithmic), not micro-optimisation.
  - V44Y/CXD still spike to 1–2 ms on 5–6-order blocks.
- Profilers: `selfplay --slow-us N` (per-turn phase and top-5 stage breakdown), `--lat-dump FILE`
  (per-step times), `terminal::TPROF`.
